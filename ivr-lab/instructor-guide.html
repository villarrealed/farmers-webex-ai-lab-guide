Instructor Guide — IVR Intent Engine Lab

Farmers Insurance — Voice Advantage Routing Use Case

Audience: Lab instructors and facilitators | Format: Hands-on workshop

Lab Overview

Duration: ~2.5 hours (can compress to 90 min by skipping Module 5 and having participants do only scenarios 1 and 3)

Class size: Up to 10 participants (one AI Agent Studio org, 10 lab user accounts)

Difficulty: Intermediate — participants should have completed Lab 1 (policy servicing) or have basic familiarity with Webex AI Agent Studio

What makes this lab different from Lab 1

Lab 1 teaches the core Webex AI Agent Studio mechanics (create agent, knowledge base, MCP actions, test). This lab applies those skills to a realistic IVR routing use case — the emphasis is on instruction design, data-driven routing, and the retention conversation pattern.

Key concepts introduced

  • Data-driven routing: agent behavior changes based on flags returned by an API call
  • Retention conversation design: qualifying questions before transfer (not available in DTMF IVR)
  • Transfer simulation: the simulate_transfer action gives visibility into routing decisions
  • Edge case handling: unknown callers, human requests, open claims

Module Notes Instructor cues

Use these notes as real-time coaching and debrief prompts during delivery.

M1 Notes

Common issue: Participants paste instructions but forget to click Save. Symptom: agent doesn't ask for phone number, just says "how can I help?" Fix: go to Profile tab, scroll to Instructions, verify the content is there, click Save, republish.

"Notice how the instructions are structured exactly like the IVR flow document — step by step, with explicit branch conditions. The AI doesn't need to figure out the logic — you've written it out. The AI's job is to use natural language to execute the logic."

M2 Notes

The MCP server URL is the most frequent error source. If the action shows "connection failed," have participants verify they typed the URL exactly (no trailing slash, https not http).

If Render spins down the server (free tier), the first request may take 30-60 seconds while it wakes up. This looks like a failed connection but resolves itself. Tell participants: "If the first test takes a while to respond, that's normal — the server is warming up."

M3 Notes

For Scenario 2, remind participants they need to start a NEW preview session for Part B. The agent holds conversation context within a session — if they already said "yes I'm calling about my claim" in Part A, they can't re-test Part B in the same session.

M4 Notes

Scenario 3 debrief (do this as a group)

Ask: "Why do we ask if they're selling the asset before asking about the 30-day timeline?"

Answer: A customer selling their home or car is a legitimate cancel — they don't need to be saved, and sending them to Retention wastes a specialist's time and frustrates the customer. The first question filters out the legitimate cancels before investing in the retention conversation.

Ask: "What changed when you modified the retention question in Module 5?"

Point: Small instruction changes produce measurably different outcomes. This is why instruction design is a discipline — it's not "just prompting."
