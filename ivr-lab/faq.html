About the Lab

How is this lab different from Lab 1?

Lab 1 teaches the fundamentals of Webex AI Agent Studio: creating an agent, building a knowledge base, connecting MCP actions, and testing. This lab (Lab 2) applies those same tools to a realistic IVR routing scenario based on a real Farmers Insurance design document. The focus shifts from "how to use the tools" to "how to design AI behavior for complex routing logic."

Do I need to complete Lab 1 first?

Recommended but not required. If you're already comfortable with Webex AI Agent Studio (creating agents, adding actions), you can jump straight to this lab. If you've never used it before, Lab 1 is a gentler introduction.

What is RADD?

RADD stands for Real-time Agent Data Display — a Farmers Insurance API that returns caller profile data in real-time when a call arrives. In the real system, the caller's phone number is captured automatically from the call (called ANI — Automatic Number Identification) and used to look up their account before the AI even speaks. In this lab, we simulate RADD with a mock API server, and since we're using AI Agent Studio's preview mode (no real phone call), you type the phone number instead.

Why do I type a phone number instead of the call arriving with one automatically?

In a real deployment, the phone number would come from the call itself (ANI) — the IVR would look it up automatically before saying a word. In AI Agent Studio's preview mode, there's no real phone call, so there's no automatic ANI. The agent asks for your phone number as a proxy, and you type one of the five test numbers to simulate being that caller. The behavior is equivalent — the key difference is manual vs. automatic input.

Testing

Can I test the same scenario multiple times?

Yes — each time you open a new preview session, you start fresh. The agent doesn't remember previous sessions.

What if the agent doesn't behave as expected?

First check: did the agent call lookup_caller_by_phone? You can see tool calls in the preview panel. If it didn't call the lookup, the instructions may not be saved. Go to Profile → Instructions, verify the content is there, click Save, and republish.

The agent is routing correctly but the simulate_transfer details look wrong in the transfer log. Is that a problem?

The transfer log records exactly what your agent passed to simulate_transfer — including the intent label and destination string. If these differ from what the instructions specify, it means the agent chose slightly different wording. This is normal LLM behavior — the intent is correct even if the exact string varies. In production, you'd add enum constraints to standardize the values.

Can I test with phone numbers other than the five provided?

Yes, but they'll all return "not found" since only those five are in the simulation database. This is a good way to test the unknown caller path manually without using 555-0099.

The RADD Server

What happens if the RADD simulation server is down?

The first request to the server after a period of inactivity may take 30-60 seconds (the Render free tier spins the server down when idle). If you see a long pause or a connection error on first test, wait a moment and try again. After the first successful call, the server stays warm for the rest of your session.

How do I check if the server is running?

Open https://farmers-radd-sim-server.onrender.com/health in your browser. You should see: {"status":"ok","server":"Farmers RADD Simulation Server","tools":2,"caller_profiles":5}

Can I see all the test calls that have been made?

Yes — https://farmers-radd-sim-server.onrender.com/transfer-log shows the last 20 transfer decisions recorded by any participant's agent. This resets when the server restarts.

Agent Behavior

Why does the agent need such detailed instructions? Can't it figure out the routing logic itself?

An AI agent without instructions will attempt to be helpful, but it won't know YOUR business rules — which customers get retention conversations, when to offer automated payments, what to do with open claims. The instructions are how you encode your routing logic into the AI. Think of them as the training manual the agent reads before every single response.

I changed my agent's instructions but it still behaves the same way. Why?

Did you click Save AND Publish? Saving updates the configuration but publishing is what makes the new version active for testing. Also make sure you start a new preview session after publishing — open sessions use the previously published version.

The retention conversation seems too long / too short. How do I adjust it?

The retention script in the instructions can be modified freely. Try making the empathetic opening shorter, or changing the qualifying questions. The Tune & Explore module in Module 5 walks through this. Small wording changes can significantly affect how customers respond.

What does the agent do if a caller is angry or rude?

The instructions include a rule to "acknowledge their feelings before proceeding." For a more robust implementation, you could add a specific angry-caller path in the instructions — for example, a rule that if the caller expresses frustration, the agent acknowledges before proceeding with the routing questions.
